# First open, providers, and goals

On its first interactive launch, Atlias asks which model route to use. The screen offers direct ChatGPT personal sign-in, separate OpenAI, Anthropic, Gemini, and OpenAI-compatible API billing, native Claude Code and Codex host sessions, the unsupported Antigravity consumer embedding, or “I will just use local models using Ollama.” Choosing later or cancelling leaves setup deferred. Run `/onboarding` to reopen it. A deferred first open does not start the provider saved in an older config; `--engine echo` remains available for a no-provider diagnostic.

ChatGPT personal sign-in uses Atlias Personal's own SDK and OAuth flow. The user must approve the official consent screen; Atlias never borrows Codex or Claude credentials. It checks the authorized plan session and the configured model and reasoning effort without sending inference. If the configured `gpt-6.1-sol` and effort are not available, setup stays deferred until the user explicitly chooses a supported model and effort. API setup reads a key from its named process environment variable, never prompts for a key, and can optionally check `GET /models`; that check is not a model-access or inference guarantee. Use `/onboarding` later to add an API route, or `/auth chatgpt` to manage personal sign-in and model selection.

Ollama setup links to [Ollama's Windows download](https://ollama.com/download), asks for a localhost endpoint and installed model name, then checks only `GET /api/tags`. The user installs and starts Ollama, runs `ollama pull <model>`, selects that exact model, and reruns `/onboarding` after a connection or model-list failure. Atlias does not run inference as a setup check and local Ollama needs no account or API key.

Claude Code and Codex are explicit native host engines. Their own clients own login, model choice, tools and billing. Atlias can start the native login command and reads only a boolean authentication result; it never copies or relays a token. Claude Code's subscription flow remains inside Claude Code. Atlias does not embed the Antigravity consumer CLI; use the Gemini API route with its own key and billing or launch Antigravity as its own app.

`/goals` and `/goal` store one project-owned objective in `.atlias/goals.json`. Create one with `/goal create --rounds 3 --check "npm test" <objective>`, then inspect it with `/goals status`. Continuation is bounded by the requested round count and stored limit. A model's claim does not complete a goal: Atlias asks before running the exact configured check, records its result, and marks complete only after a passing check for the current objective revision. Update, pause, resume, and defer with `/goal update`, `/goal pause`, `/goal resume`, and `/goal defer`.

Atlias cannot control selection behavior in a portable ANSI terminal. In an active Windows Terminal session, `/copy-on-select status` reports the host's root `copyOnSelect` setting. `/copy-on-select on` or `off` explains that the setting applies to every profile and that right-click pastes while enabled, then asks for confirmation before changing the Windows Terminal settings file. It preserves JSONC comments and unrelated settings. Other terminals report that selection behavior belongs to the terminal; Atlias does not poll or capture the clipboard. See [Windows Terminal interaction settings](https://learn.microsoft.com/en-us/windows/terminal/customize-settings/interaction).
